# Anarc telemetry backend (Convex)

Phases 3 and 5 of the telemetry plan: ingestion of the fixed daily rollup ping
and an auth-gated rollup dashboard. This directory is self-contained: no Rust
file, root manifest or shared tool was changed.

## Files

| File | Purpose |
| --- | --- |
| `functions/validation.mjs` | Dependency-free wire validator (no Convex/Node imports). |
| `functions/validation.d.mts` | Types for the validator. |
| `functions/validation.test.mjs` | `node:test` coverage of the validator. |
| `functions/http.ts` | `POST /ping` HTTP action; body cap, parse, validate, rate limit, store. |
| `functions/ingest.ts` | Internal mutation: the only write path; rate limits + rollups in one transaction. |
| `functions/rateLimiter.ts` | Rate-limiter component client; per-install and global limits. |
| `functions/convex.config.ts` | Registers the rate-limiter component and declares env vars. |
| `functions/schema.ts` | Tables: `daily`, `agent_daily`, `installs`. |
| `functions/dashboard.ts` | Auth-gated query computing DAU/WAU/MAU and all rollup splits. |
| `functions/_generated/` | Generated by `convex dev`; commit it. |
| `convex.json` | Points the CLI at `functions/` so this directory is self-contained. |
| `package.json` / `package-lock.json` | Pinned `convex` and `@convex-dev/rate-limiter` versions. |

## Setup and deployment

Run all CLI commands **from this `convex/` directory**; `convex.json` sets
`functions` to `functions/`, and `.env.local` (gitignored) selects the
deployment.

```bash
npm ci
./node_modules/.bin/convex dev --once    # push + regenerate functions/_generated
./node_modules/.bin/convex deploy        # only with explicit prod approval
```

`convex dev`/`deploy` reads `functions/convex.config.ts` and installs the
`@convex-dev/rate-limiter` component automatically.

Set secrets via **stdin**, never via `$(...)` or a literal argument, so they
cannot land in shell history:

```bash
umask 077
openssl rand -hex 32 | ./node_modules/.bin/convex env set TELEMETRY_ADMIN_TOKEN
printf '100000' | ./node_modules/.bin/convex env set TELEMETRY_GLOBAL_DAILY_LIMIT
./node_modules/.bin/convex env list --names-only   # names only; never prints values
```

## Request contract

`POST /ping`, `Content-Type: application/json`, body ≤ 4096 UTF-8 bytes.
The body is the exact JSON produced by `crates/anarc-telemetry/src/schema.rs`
(`schema_version`, `app_version`, `distro`, `arch`, `install_id`, `agent`).
Unknown fields are rejected at every object level; enum codes, bucket bands and
UUID v4 format are checked by `validation.mjs` before any write. `app_version`
is capped at 128 characters (the 4 KB body cap still applies).

Responses:

- `200 {"ok":true}` — accepted.
- `400 {"error":"<code>:<path>"}` — malformed/invalid body; code strings are fixed validator codes, never request data.
- `413 {"error":"body_too_large"}` — body over 4 KB.
- `429 {"error":"install_rate_limit" | "global_rate_limit"}` — daily limit reached.

Privacy: the only header read is `content-length`, and only to reject oversized
bodies early. IPs, user agents and all other headers are never read or stored.
No exact timestamp is stored: `day` is the server's UTC `YYYY-MM-DD`.
Tables hold counts, enum codes and fixed-length bucket histograms only.

## Rate limiting

`@convex-dev/rate-limiter` is wired in `convex.config.ts` and used from
`rateLimiter.ts`:

- `pingPerInstall`: fixed window, rate 1, period 1 day, `start: 0` (epoch-aligned,
  therefore UTC midnight), keyed by `install_id`.
- `globalPing`: fixed window over all pings, rate from
  `TELEMETRY_GLOBAL_DAILY_LIMIT` (default 100000), same UTC window.

Both are consumed inside a single Convex mutation, so concurrent requests
cannot exceed either cap. `ingest.ts` also checks the global cap without
consuming it before writing.

**Deviation:** none. The component dependency is available and pinned in
`convex/package.json`; no table-based fallback was needed. If you remove the
component, you must replace both limits with an equivalent Convex-table
limiter — do not deploy without rate limiting.

## Aggregate storage

- `daily`, key `(day, version, distro, arch)`: ping count, agent-ping count,
  activity counts by action and by error code.
- `agent_daily`, key `(day, harness)`: ping count plus bucket histograms for
  sessions, actions, token ratio, snapshot latency, element count,
  ref-resolve success, errors and plugins.
- `installs`, key `install_id`: `firstSeen` and `lastSeen` UTC days. These two
  fields also drive DAU/WAU/MAU.

Histogram lengths match the Rust bands: sessions 5 slots (0..4), token ratio /
snapshot ms / element count 4 slots (0..3), all others 10 slots (0..9).

## Dashboard

No Convex Auth provider exists in this repo, so `functions/dashboard.ts` uses the
configured `TELEMETRY_ADMIN_TOKEN` env var: every call must pass the same
string in `adminToken`; missing or mismatched tokens raise `Unauthorized`.
The token is compared without early exit and is never logged or stored.
To use real Convex Auth instead, replace the `tokenEquals` check with
`ctx.auth.getUserIdentity()` and an allow-list check.

Call the query (from a trusted admin client only):

```ts
const stats = await client.query(api.dashboard.summary, {
  adminToken: process.env.TELEMETRY_ADMIN_TOKEN!,
  rangeDays: 30,
});
```

Returned fields:

- `activity`: `dau` (today), `wau` (last 7 UTC days), `mau` (last `rangeDays`,
  default 30), total pings.
- `agent`: adoption %, harness split, median token-ratio bucket and median
  snapshot-latency bucket (with their full histograms).
- `versionSplit`: pings and share by `(app_version, distro)`.
- `calls` and `errors`: counts, plus error rates per 1000 pings.

Bucket band meanings are defined in `crates/anarc-telemetry/src/buckets.rs`:
token ratio 0 `<10%`, 1 `10-24%`, 2 `25-49%`, 3 `50%+`; snapshot ms 0 `<10`,
1 `10-49`, 2 `50-199`, 3 `200+`. The dashboard reports band codes, never raw
measurements. Convex query read limits apply; keep `rangeDays` small for large
deployments (capped at 365 here).

## Tests and portability

```bash
node --test functions/validation.test.mjs
# or, from convex/
npm test
```

`functions/validation.mjs` has no Convex imports and no runtime-specific APIs, so the
same function can be reused verbatim by a future Axum + Postgres port; only
the storage and rate-limit adapters would change.
